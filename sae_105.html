Projet 1.05 – Traiter des données

Projet 1.05 RT3 – Outils Informatiques Semestre 1 Projet en Binôme

Contexte & Cahier des charges

Le traitement automatisé de flux de données massives et l'interaction avec des architectures applicatives distantes constituent des compétences clés pour un technicien R&T. Qu'il s'agisse de collecter des indicateurs de supervision ou d'analyser des journaux d'événements de sécurité, la maîtrise du scripting est indispensable.

Le cahier des charges imposait de concevoir, en binôme, un ensemble de scripts en langage Python. Notre mission : interroger des API REST (OpenStreetMap et Overpass), extraire et trier des volumes de données géographiques brutes au format JSON, et générer de manière totalement autonome des fiches documentaires de synthèse exploitables aux formats Markdown et HTML.

Démarche de production : De l'acquisition à la restitution

Pour mener à bien ce projet d'ingénierie logicielle, nous avons structuré notre travail selon une chaîne de traitement séquentielle et modulaire.

Étape 1 : Requêtage d'API et extraction de données

Apprentissage mobilisé (AC13.01) : Utiliser les systèmes informatiques et outils métiers. Nous avons utilisé la bibliothèque requests de Python pour formuler des requêtes HTTP en langage OverpassQL, afin de cibler et récupérer les structures JSON correspondant aux commerces de l'agglomération étudiée.

Étape 2 : Parsing des données JSON et Gestion des erreurs

Apprentissage mobilisé (AC13.02) : Lire, modifier et écrire un programme. Il s'agissait de parcourir algorithmiquement les dictionnaires récupérés pour isoler les coordonnées et les attributs de chaque nœud géographique.

🚨 Analyse d'incident : Exception "KeyError" et arrêt du traitement par lots

Le problème : Lors du traitement de larges volumes de données, notre script s'interrompait brutalement (crash). Les bases de données OpenStreetMap étant collaboratives, leur structure est hétérogène : certains commerces n'avaient pas de numéro de téléphone ou de nom de rue renseigné. En tentant d'accéder directement à ces clés inexistantes (ex: element['tags']['phone']), Python levait une erreur fatale KeyError.

⚙️ Analyse et remédiation technique :

Pour rendre notre code résilient face à l'incertitude des données externes, nous avons implémenté une logique de programmation défensive. Nous avons remplacé les appels directs par l'utilisation de la méthode sécurisée .get(), qui permet de définir une valeur de substitution (fallback) si la clé est absente (ex: "Non renseigné"). Le script a ainsi pu traiter 100% des requêtes sans la moindre interruption.

📸 Preuve technique : Programmation défensive

Cette capture de notre code source démontre la remédiation apportée au niveau du dictionnaire Python, garantissant la stabilité du parsing des données JSON.

Étape 3 : Traitement d'images matricielles

Apprentissage mobilisé (AC13.02) : À l'aide de la bibliothèque Pillow (PIL), nous avons développé des fonctions mathématiques pour indexer les tuiles cartographiques, télécharger les portions d'images requises, et y superposer un marqueur visuel aux coordonnées GPS exactes du lieu.

Étape 4 : Industrialisation documentaire

Enfin, notre script consolide les textes extraits et l'image générée en instanciant un fichier Markdown, immédiatement converti en une page web HTML standardisée via le module markdown.

Bilan du Projet & Prise de recul

Ce travail mené en binôme a consolidé mes compétences en développement logiciel. Manipuler des structures de données complexes et automatiser des processus m'a fait prendre conscience de l'importance de concevoir des programmes tolérants aux erreurs.

Compétences consolidées

La maîtrise des requêtes HTTP (API), l'exploitation de la bibliothèque Pillow pour la manipulation d'images matricielles, et la gestion rigoureuse des exceptions en langage Python.

Évolution des pratiques

Si je devais faire évoluer cette application, j'y intégrerais un système de base de données local (SQLite) afin de mettre les réponses de l'API en cache, ce qui éviterait de surcharger le réseau lors des exécutions successives du script.

📚 Vocabulaire Technique

API REST : Interface permettant à un programme de communiquer et d'échanger des données avec un serveur via des requêtes HTTP.

JSON : Format de données textuel léger, basé sur des paires clés-valeurs, universellement utilisé pour structurer les réponses d'API.

Parsing : Action d'analyser syntaxiquement un flux de données brutes pour en extraire des variables exploitables par le code.

Programmation Défensive : Pratique consistant à anticiper et traiter les cas d'erreurs (données manquantes, crashs potentiels) pour garantir la stabilité d'un script.
